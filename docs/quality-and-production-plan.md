# Quality and production hardening plan

Этот документ фиксирует слабые места проекта и показывает, как они закрыты или будут закрываться при переходе к production.

## Уже усилено

- Добавлен `Dockerfile` для сборки приложения.
- Добавлен `docker-compose.yml` для запуска Next.js и PostgreSQL одной командой.
- PostgreSQL автоматически инициализируется из `database/schema.sql`.
- Добавлена папка `database/migrations` с правилами ведения миграций.
- В базе добавлены триггеры для `updated_at`, `started_at`, `completed_at`, audit log и защиты `created_at`.
- Внешние интеграции Trello и Resend являются необязательными: при отсутствии ключей приложение продолжает работать.

## Что нужно для production

1. Подключить полноценный инструмент миграций: Drizzle Kit, Prisma Migrate или node-pg-migrate.
2. Добавить E2E-тесты на Playwright для полного сценария клиент → менеджер → разработчик → клиент.
3. Добавить регулярный backup PostgreSQL через `pg_dump`.
4. Вынести сложную бизнес-логику из API routes в service layer.
5. Добавить централизованную валидацию входных данных через Zod.
6. Подключить HTTPS, secure cookies и CSRF-защиту для production-домена.
7. Провести UX-тестирование и сравнить время составления ТЗ вручную и через NeuralBrief.

## Минимальный E2E-сценарий

1. Пользователь регистрируется как клиент.
2. Клиент проходит AI-чат и формирует brief.
3. Клиент отправляет brief менеджеру.
4. Менеджер принимает проект и назначает разработчика.
5. Разработчик переводит задачу в `in_progress`, затем в `review`.
6. Менеджер закрывает задачу.
7. Клиент подтверждает результат и ставит оценку.
8. Директор видит статистику и запись в audit log.
