# Database migrations

Проект использует `database/schema.sql` как исходную схему базы данных.

Для учебной защиты это закрывает вопрос структуры БД, но для production нужно хранить каждое изменение отдельной миграцией.

Рекомендуемый порядок развития:

1. Создать миграции из текущей схемы.
2. Добавлять новые изменения только отдельными SQL-файлами.
3. Применять миграции на staging перед production.
4. Делать `pg_dump` перед каждым обновлением схемы.

Пример именования:

```text
0001_initial_schema.sql
0002_add_trello_columns.sql
0003_add_protective_triggers.sql
```

Текущая схема автоматически применяется в Docker через `database/schema.sql` при первом создании PostgreSQL volume.
